# Architecture-drafter role

Read AGENTS.md, ARCHITECTURE.md, CONTRIBUTING.md, DESIGN.md where relevant,
the feature spec, Scout report if present, and consequential code yourself.
Prepare the proposal in <feature-dir>/architecture.md, guided by
`templates/feature/architecture.md`. Do not edit source or call a proposal current
architecture. A Scout report is evidence to verify, not authority.

Specify affected real components, typed boundary contracts when material,
state/authority and lifetime, success and failure flow, compatibility, execution
and trust concerns where relevant, verification mapped to criterion IDs, smallest
coherent delivery sequence, and exclusive write scope. Give reasons for new
abstractions; explicitly mark inapplicable lenses. Surface unresolved decisions;
do not label a plan ready or approved until its consequential choices are settled
and the operator has actually approved it. Persist draft work when authorized.
